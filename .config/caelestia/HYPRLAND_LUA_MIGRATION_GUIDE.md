# Hyprland 0.57+ Lua Migration Guide for Caelestia Shell

<task_briefing>
<objective>
Safely, cleanly, and securely migrate the user's Hyprland configuration from legacy `hyprlang` (`.conf`) syntax to native Lua (`.lua`) in strict alignment with Hyprland 0.57+ specifications and Caelestia desktop shell (`caelestia-dots/caelestia`) architecture.
</objective>

<primary_directives>
1. **Safety First**: Take verifiable, restorable backups before modifying, unlinking, or deleting any file.
2. **Architecture Compliance**: Respect Caelestia's design rules. Never modify core dotfiles inside `~/.config/hypr/` directly. Place all custom settings in `~/.config/caelestia/hypr-vars.lua` and `~/.config/caelestia/hypr-user.lua`.
3. **Preserve User Settings**: Accurately translate user preferences (Turkish keyboard layout, dual monitors DP-1 & HDMI-A-1, dynamic-cursors plugin config) into valid Hyprland Lua syntax.
4. **Clean Symlink Separation**: Transition from legacy symlinked setups (`~/.config/hypr -> ~/.local/share/caelestia/hypr`) to upstream Caelestia Lua deployment (`~/.local/state/caelestia/dots/hypr`).
</primary_directives>
</task_briefing>

<caelestia_lua_architecture>
<specification>
Upstream Caelestia (`caelestia-dots/caelestia`) structures Hyprland Lua as follows:

1. **Entry Point (`~/.config/hypr/hyprland.lua`)**:
   - Appends `~/.config/caelestia/?.lua` to `package.path`.
   - Requires `hypr-vars` (`~/.config/caelestia/hypr-vars.lua`) and merges overrides into `variables.lua`.
   - Loads core modules:
     - `hyprland.env`
     - `hyprland.general`
     - `hyprland.input`
     - `hyprland.misc`
     - `hyprland.animations`
     - `hyprland.decoration`
     - `hyprland.group`
     - `hyprland.execs`
     - `hyprland.rules`
     - `hyprland.gestures`
     - `hyprland.keybinds`
   - Finally requires `hypr-user` (`~/.config/caelestia/hypr-user.lua`) to execute user custom rules, monitors, and inputs.

2. **User Overrides (`~/.config/caelestia/hypr-vars.lua`)**:
   - Must return a Lua table of key-value pairs matching `variables.lua`.
   - Used for default apps, keybind replacements, gap sizes, border sizes, colors.

3. **User Configs (`~/.config/caelestia/hypr-user.lua`)**:
   - Executes arbitrary Hyprland Lua commands at the end of the config lifecycle.
   - Used for monitors (`hl.monitor`), input overrides (`hl.config({ input = ... })`), and plugins (`hl.config({ plugin = ... })`).
</specification>
</caelestia_lua_architecture>

```lua
hl.monitor({

    position = "auto",

    output   = "HDMI-A-1",
    mode     = "1920x1080@60",
    position = "auto",
    scale    = 1,
})

------------------
----  INPUT   ----
------------------
-- Turkish Q keyboard configuration
-- Note: In XKB (xkeyboard-config), the default ("") variant of "tr" is Turkish Q;
-- "qwerty" is not a valid XKB variant for "tr" and fails keymap compilation.
hl.config({
    input = {
        kb_layout  = "tr",
        kb_variant = "",
    },
})

------------------
---- PLUGINS  ----
------------------
-- Dynamic Cursors plugin configuration
-- Guarded with hl.get_loaded_plugins() + pcall so Hyprland 0.57+ does not emit
-- unknown-option errors before the plugin is loaded, and applies automatically once loaded.
local function is_plugin_loaded(target)
    if type(hl.get_loaded_plugins) ~= "function" then
        return false
    end
    for _, p in ipairs(hl.get_loaded_plugins()) do
        if p.name and (p.name == target or p.name:find(target, 1, true)) then
            return true
        end
    end
    return false
end

if is_plugin_loaded("dynamic-cursors") then
    pcall(function()
        hl.config({
            plugin = {
                ["dynamic-cursors"] = {
                    enabled   = true,
                    mode      = "stretch",
                    threshold = 2,
                    rotate = {
                        length = 20,
                        offset = 0.0,
                    },
                    tilt = {
                        limit        = 5000,
                        ["function"] = "negative_quadratic",
                        window       = 100,
                        full_tilt    = 60,
                    },
                    stretch = {
                        limit        = 5400,
                        ["function"] = "quadratic",
                        window       = 90,
                    },
                    shake = {
                        enabled   = false,
                        threshold = 6.0,
                        base      = 4.0,
                        speed     = 4.0,
                        timeout   = 2000,
                        nearest   = true,
                        effects   = false,
                    },
                },
            },
        })
    end)
end
```

<step_by_step_execution_protocol>
<step index="1" title="Create Full Safety Backups">
<action>
Before any alteration or removal, package existing configurations into dated archive files:
```bash
BACKUP_TIMESTAMP=$(date +%Y%m%d_%H%M%S)
mkdir -p ~/.config/caelestia/backups

# Backup user configurations
cp -a ~/.config/caelestia ~/.config/caelestia/backups/caelestia_${BACKUP_TIMESTAMP}

# Backup existing hypr directory or symlinked target
tar -czf ~/.config/caelestia/backups/hypr_legacy_${BACKUP_TIMESTAMP}.tar.gz -C ~/.local/share/caelestia hypr
```
</action>
</step>

<step index="2" title="Write New User Lua Configs">
<action>
Create `~/.config/caelestia/hypr-vars.lua` and `~/.config/caelestia/hypr-user.lua` with the target code blocks defined above:
```bash
# Verify directory
mkdir -p ~/.config/caelestia

# Create hypr-vars.lua if absent
# Populate hypr-user.lua with monitor, input, and plugin configs
```
</action>
</step>

<step index="3" title="Archive Legacy .conf Files">
<action>
To avoid confusion or accidental sourcing:
```bash
if [ -f ~/.config/caelestia/hypr-user.conf ]; then
    mv ~/.config/caelestia/hypr-user.conf ~/.config/caelestia/hypr-user.conf.migrated
fi

if [ -f ~/.config/caelestia/hypr-vars.conf ]; then
    mv ~/.config/caelestia/hypr-vars.conf ~/.config/caelestia/hypr-vars.conf.migrated
fi
```
</action>
</step>

<step index="4" title="Deploy Upstream Caelestia Lua to ~/.config/hypr">
<action>
Replace the legacy symlink / autogenerated template with the verified official Caelestia Lua files located in `~/.local/state/caelestia/dots/hypr`:

```bash
# Remove old symlink
if [ -L ~/.config/hypr ]; then
    rm ~/.config/hypr
fi

# Deploy fresh directory from state repository
mkdir -p ~/.config/hypr
cp -r ~/.local/state/caelestia/dots/hypr/* ~/.config/hypr/
```
Ensure directory permissions and structure:
- `~/.config/hypr/hyprland.lua`
- `~/.config/hypr/variables.lua`
- `~/.config/hypr/hyprland/*.lua`
- `~/.config/hypr/scheme/default.lua`
- `~/.config/hypr/utils/*.lua`
</action>
</step>

<step index="5" title="Validate and Reload">
<action>
1. Check syntax of Lua files:
   ```bash
   luac -p ~/.config/hypr/hyprland.lua ~/.config/caelestia/hypr-user.lua ~/.config/caelestia/hypr-vars.lua
   ```
2. Trigger Hyprland configuration reload:
   ```bash
   hyprctl reload
   ```
3. Restart Caelestia shell if required:
   ```bash
   caelestia shell -d
   ```
</action>
</step>
</step_by_step_execution_protocol>

<rollback_procedure>
<scenario trigger="Hyprland crashes or black-screens on reload">
<procedure>
1. Switch to a TTY (`Ctrl + Alt + F3`).
2. Log in with user credentials.
3. Restore the backup:
   ```bash
   # Restore previous symlink
   rm -rf ~/.config/hypr
   ln -s /home/atlasata/.local/share/caelestia/hypr ~/.config/hypr
   
   # Restore previous .conf files if needed
   mv ~/.config/caelestia/hypr-user.conf.migrated ~/.config/caelestia/hypr-user.conf 2>/dev/null || true
   mv ~/.config/caelestia/hypr-vars.conf.migrated ~/.config/caelestia/hypr-vars.conf 2>/dev/null || true
   ```
4. Restart session manager / compositor or return to GUI (`Ctrl + Alt + F1` or `F2`).
</procedure>
</rollback_procedure>
